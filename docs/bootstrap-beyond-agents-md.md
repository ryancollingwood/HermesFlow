# Bootstrap notes — beyond AGENTS.md

`AGENTS.md` is the canonical, maintained source of conventions for this repo
and should be read first. This file fills in things a new agent needs that
aren't in there yet, as of 2026-06-27 — mostly a newer subsystem that landed
without an `AGENTS.md` update, plus repo-navigation context that's useful but
not "rules."

## Gap: Directus is undocumented in AGENTS.md

`docker-compose.directus.yml` is a fully wired optional subsystem — installer
flags, Makefile lifecycle, secrets, backup — but it is **not mentioned
anywhere in AGENTS.md**, which only uses Baserow as the optional-extension
reference example. When touching Directus, treat Baserow's section in
AGENTS.md as the pattern to follow, and reconcile against what Directus
actually does (they differ in a few ways — see below). Consider proposing an
AGENTS.md update if you do substantial Directus work.

Key facts about Directus, gathered from the code (not from AGENTS.md):

- Enabled via `--with-directus` (both installers) or `make directus`;
  reverted with `make directus-revert`.
- Secrets: `DIRECTUS_DB_PASSWORD`, `DIRECTUS_KEY`, `DIRECTUS_SECRET`,
  `DIRECTUS_ADMIN_PASSWORD` — generated by `make secrets` / `ensure_secret` in
  both installers (Makefile:96-100).
- Unlike Baserow (its own dedicated DB), Directus shares the **`collection_db`**
  Postgres instance with Baserow and Windmill's "collection" role. See
  `collection_db/initdb/01-init.sh`: three isolated schemas in one physical DB —
  `baserow` (Baserow-only, no external writes — its DDL is internally managed),
  `directus` (Directus system tables), `collection` (shared business data,
  writable by both `directus` and `windmill_collection` roles, *not* by
  baserow). Baserow↔collection sync goes through Baserow webhooks, not SQL.
- MCP exposure for Directus is **native** (v11.12+) and enabled via the
  Studio UI (Settings → AI) — not a compose/env setting, unlike Baserow's MCP
  bridge which is baked into the Hermes image (see AGENTS.md's "Runtime / agent
  (MCP) bootstrap" section). Don't expect a `directus-mcp` Makefile target —
  there isn't one, by design.
- No native "AI field" type — AI-assisted generation goes through a Directus
  Flow calling Ollama's `/v1` endpoint over the `inference` network, or the
  built-in AI Assistant chat panel pointed at the same endpoint.
- `make backup` already dumps Collection Postgres unconditionally (covers
  Baserow + Directus + the shared `collection` schema together) — see
  Makefile:556.

### CI does not validate the Directus override

`.github/workflows/ci.yml`'s `compose` job merges and validates
`docker-compose.gpu.yml` and `docker-compose.baserow.yml` against the base
file, but **not** `docker-compose.directus.yml`. If you change anything in
that override (or in shared bits like `collection_db` or `.env.example`
variables it depends on), validate locally —
`docker compose -f docker-compose.yml -f docker-compose.directus.yml config -q`
— since CI won't catch a break there.

## Repo navigation notes (not rules, just orientation)

- `collection_db` (top-level dir) is the shared Postgres used by Baserow,
  Directus, and Windmill's collection role — it isn't its own service block
  in the base `docker-compose.yml`'s service table in AGENTS.md or README;
  it's provisioned by whichever optional override needs it first.
- `docs/` currently has one file: `baserow-accounts-and-sharing.md`. AGENTS.md
  says to add `docs/<feature>*.md` for deeper caveats when warranted — there
  isn't an equivalent Directus doc yet.
- `hermes/README.md` has the full rationale for the lazy-install security
  model referenced (but not fully reproduced) in AGENTS.md's "Adding Python
  packages for Hermes" section.
- `windmill/SYNC.md` has the full sync-scope breakdown; AGENTS.md only
  summarizes it.
- CI is two workflows: `.github/workflows/ci.yml` (compose validation +
  Caddyfile validation + Python/ruff/YAML checks + a windmill
  script↔metadata↔lockfile consistency check — all static, no running
  server) and `.github/workflows/hermes-image.yml` (path-filtered to
  `hermes/**`, builds the derived Hermes image to confirm `requirements.txt`
  pins resolve against `LAZY_DEPS`).
- Full Makefile target list (for quick lookup, not reproduced in AGENTS.md):
  `bootstrap`, `wizard`, `secure`, `secrets`, `apikey`, `init`, `check`,
  `fix-permissions`, `pull`, `build`, `up`/`down`/`restart`, `logs`, `ps`,
  `health`, `backup`, `validate`, `lint`, `ci`, `hermes-heal`,
  `hermes-workspace`, `hermes-secure`, `headroom`/`headroom-revert`,
  `mlx`/`mlx-revert`/`mlx-status`, `memory`/`memory-revert`,
  `hindsight-mlx`/`hindsight-mlx-revert`, `aux-cloud`/`aux-local`/
  `aux-hindsight`/`aux-status`, `windmill-push`/`windmill-pull`/
  `windmill-check`, `baserow`/`baserow-revert`/`baserow-mcp`,
  `directus`/`directus-revert`.
